execution. Continue the standing autonomous mandate without new cost, credential,

## Narrow intervention and interpretation

A Java main returning zero establishes successful execution, not that expected
conditions were asserted. Future helper receipts must distinguish these claims:
versioned schema; `execution_succeeded` instead of a correctness-like `passed`;
assertions enabled, assertion coverage unknown, correctness not established.
Compile/runtime/timeout/output-limit failures remain failures. Source/binary
bindings and logs remain. No source-based assertion-count heuristic is used.

Generic candidate documentation asks for each tested claim's expected condition,
actual check, evidence and limitations, explicitly marking printed observations
or untested claims. It supplies no bot-specific scenario, strategy, prior source,
review, score or evaluator information. Candidate-created test oracles remain
untrusted evidence, not independently established game correctness. This is a
small feedback-quality iteration, not proof that wording alone improves bots.

## Required gates before launch

1. Exact code/protocol heads have passing CI, generic print-only/empty/true-assert
   fixtures demonstrate execution-only reporting, failed assertions remain
   nonzero, compilation failure is execution-not-run; existing bounded helper
   and source snapshot tests pass. Independent review checks these claims.
2. One official lectureplayer integration submission, at most8games on the
   unchanged schedule, mandatory note→submit→result→bounded-replay. Preserve all
   attempts; no automatic retry. Check terminal coverage and both-team activity.
3. Use the shared host-Python launcher, fixed offline Nix adapter worker command,
   bounded same-process probe and exact integration/live parity binding.
   Do not nest the service itself in Nix. Ambient cross-launch environment
   equality is not attested; actual live probe+worker share process context.
4. Independent source-empty export review, zero live mailbox/submissions, hashes
   of every fixed input and generic kickoff, parent readiness acceptance.
5. Stop on infrastructure_failure/run_halted/uncertain submission. Otherwise
   candidate chooses a submitted source and records limitations, then stops.
   Resolve accepted service work, stop service and freeze selected source,
   binaries, all versions/receipts and static input inventory before evaluator
   release. Review code/process blind to evaluation scores and fix review hash.
