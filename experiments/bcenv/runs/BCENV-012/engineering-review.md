## Storage: accepted narrow semantics, not a hard cap

`services/storage_guard.py` measures logical regular-file lengths recursively in the service root plus attached mailbox, deduplicating overlapping roots. It includes in-root temporary/child outputs, source/build/package copies, logs and request/response/control files; candidate workspace siblings, external temporary files and shared runtime/map/opponent roots are excluded. Hard links count per entry; sparse files count logical length. The fixed threshold is1,073,741,824 bytes and the actual guard matches the resolved profile.

Checks occur at admissions, adapter boundaries, training completion, validation-copy/work boundaries and immediately before lock/selection. After-operation checks run in `finally` on exceptional paths too. Crossings, unsupported filesystem entries and scan/evidence-write failures latch failure and halt further work. Checkpoints record wall and monotonic time; append/write failures are best-effort evidence, not guaranteed full-disk durability.

Important limitations are now explicit in code/docs/protocol:

1. This is a sampled high-water detection/admission guard, not an OS quota, reservation, physical-block measurement or numeric overshoot bound. Running children are not instantaneously canceled by a storage failure.
2. Ordinary temporary-file deletion racing a scan may conservatively halt below the byte threshold. A synthetic disappearing-entry test covers this failure mode. This is an availability risk, not proof storage was exceeded; no silent scan/game retry is added.
3. A pre-selection crossing prevents choice authorization. If the selection's own later control receipt pushes usage over threshold, the already-authorized immutable choice stays selected and subsequent work halts. Do not retroactively describe it as rejected or promise selection receipt overhead cannot cross the limit.
4. The checkpoint log itself adds bytes after measurement. Full-disk errors can prevent a complete stop/receipt record. Explicit process-stop evidence remains necessary; a namespace process listing alone is not a global cleanup attestation.
